# studio

Progress Studio — React + TypeScript + Vite port of the QS model verification handoff. The current app has hash-routed Model, Mapping, Data, Bill and Review pages with a thin tool rail. The old single-file studio `ifc-qto.html` stays in place.

Read this file before using this folder.

## Rule

- Create a file or folder here: update this `route.md` in the same change.
- Delete a file or folder here: update this `route.md` in the same change.
- Replace a file: update this `route.md` only when the function of that file or folder has completely changed.

## Scope

The app uses hash routes: `#/mapping` (also aliased from `#/model`), `#/data`, `#/bill` and `#/review`. See `docs/system-architecture.md` for the current canonical system architecture, project-scoped storage and Option A–F pipeline rules. `docs/nec-option-system-architecture.md` remains as historical design detail. The rail changes the URL and renders the matching page; it never opens a popup. There is no horizontal top bar. A 58px icon-only rail holds the product logo and the five step icons; the bottom avatar opens the account popup. Files and Views live only in the logo menu.

The logo menu is a dark menu with matching dark cascading submenus. Menu actions open a centered light modal (Files, Views) or perform a direct action (import, export bill, section toggles); the File submenu does not contain project settings. The Model page is a multi-view workspace with a full-width View Function Bar at the top of the 3D canvas. The Project Browser nests drawings under their IFC file and lists elements by IFC class, with no class label or status dot on element rows; 360 views are not listed there. Enabling 360 views from Views opens the first 360 walkthrough already docked. Drawings and 360 views open docked by default; the Float button returns one to the canvas, where it can be dragged and will show a blue dashed dock preview before snapping to the right. Docked windows have square corners and take physical width from the canvas. The BQ list is a solid white, read-only table spanning the full workspace width below the canvas and dock; its top edge drags to resize the panel and it has an item search. The selected line badge remains a floating popup hidden by default and opened from the Views modal. Element properties open in the left dock when an element is selected. There is no status footer. Routed pages have no top bar.

Current workspace behaviour:
- The QS review Bill of quantities panel has a final **CE** column showing CE amounts for the affected BQ items.
- The app opens at `#/home`. The home has a light sidebar headed **AI Progress Checking**, with only a **Create project** button. The main area shows **Hello Dicky**, one **Project** tab and a project table (Type, Name, Number, Standard, NEC Option). Create project opens a modal with Project Name, Project Number, Description, Standard (HKSMM4 / CESMM) and NEC Option (A–F). The option is stored on the project and shown with its main pricing document: A/C use Activity Schedule, B/D use Bill of Quantities, E uses cost records, and F uses Activity Schedule + cost records pending confirmation. The Mapping Model create dialog marks the option's main pricing document and requires it before creating a mapping. Project standard badges use the BQ badge shape (4px radius, 22px high, uppercase). The logo menu has a single Project Browser item that returns to the project home. Projects are stored in `apc.projects.v1`; selecting one opens `#/bill`. The Document Management subnav overlaps the flow tabs instead of shifting them. Compensation Event is an active flow: its CE records page mirrors BQ, with a white + Import CE action, search, CE documents table, OCR READY badge and row menu. CE import uses the BQ single-file card (CE badge, file icon, name, type/size, progress, status, remove), then asks which BQ record the CE links to; AI automatically links the CE items to the appropriate BQ items before running the 10-second OCR processing popup. The link is stored in `apc.ce-links.v1`. The AI OCR result shows the CE document preview, extracted fields, OCR text and priced items, and carries a `Relink BQ` action that reopens the BQ picker and lets AI relink the items. The processing popup has no bottom footer line. CE records persist in `apc.ce-records.v1`. The Cleanse BQ table places a plain CE column immediately after Rate. Its value is the signed sum of the assessed values of the CEs linked to the BQ item; with no linked CE the cell is `—`. The original Amount HK$ (BIM) and Amount HK$ columns never change, and an additional column shows Final Amount HK$ (original amount + net CE); Final Amount HK$ (BIM) has been removed. The CE cell uses the same plain numeric style as Rate, and clicking the BQ row expands the CE detail. Clicking the CE value expands the linked CE details (title, CE No., date, reference and assessed value); clicking a CE detail opens its AI OCR result. The Model review BQ table uses the same CE/net/Final Amount columns, and BQ Details section 3 shows the BQ amount change with CE applied. A `Linked documents` button opens a draggable floating panel listing the CE documents and invoices linked to that BQ. The BQ page has no summary dashboard strip. The BQ records page uses a SaaS dashboard layout: BQ records title with subtitle and a white + Import button, icon flow tabs, an All records/search toolbar, an airy borderless table without selection checkboxes, uppercase headers, Pending/Confirm tinted badges and a row ⋯ menu; rows open on click.

- The rail is ordered by module: 01 Document Management, 02 Measurement Library, 03 AI Scanning, 04 Mapping Model, 05 eCheck Payment.
- **AI Scanning** (`#/data`) is rail item 03. The library has a top nav for BIM models only; Point clouds and Drawings are no longer top-level library tabs. BIM cards show a Processing, In review or Cleanse stage badge and open the result. Drawings and point clouds are attached during the IFC import and shown with the model result. The preview is a 640×420 JPEG captured from the 3D viewport when the model finishes loading, stored on the asset in `apc.scan-assets.v1`. The IFC import has three steps: the IFC model first, optional drawings (which travel with the model result), then an optional master programme (`.xer` / `.xml`, Excel or PDF). The programme travels with the scanning run; without it the programme panel, 4D timeline and programme toolbar button are hidden. Point clouds are no longer imported on their own from a top-level tab. Imported IFC files are parsed in the browser by `src/lib/ifc/`: web-ifc (CDN 0.0.57) is the primary engine and reports loading, opening, property, geometry and preparation steps; if the CDN or WASM is unavailable the built-in STEP reader takes over. Elements keep their real triangle geometry in world space (rendered directly, with a bounding box kept for focusing, picking helpers and exports); meshes are cached in IndexedDB. Properties and materials are read from both instance property sets and type property sets (`IfcRelDefinesByType` → `HasPropertySets`); material lookup accepts `Material`, `Materials`, `Structural Material`, `Material Name` and `IfcMaterial` keys, plus material associations on the element or its type. Opening a BIM card shows the AI Progress Checking result: the BIM model and a generated point cloud in two side-by-side tiles, a floating Point cloud verification panel, and a docked Master programme view when a programme was imported; there are no BQ or cost tabs. The AI Progress Checking element table shows Element, IFC class, Storey, Qty, optional Programme activity/Activity ID/Start/End/Late start/Late end/Delay, Progress and Finding; mapping columns (Material, SMM library item, BQ/Activity item, Status, Issue, Action) have been removed. The BIM tile colours elements red under 50%, amber 50–90% and green above 90%. The Master programme view is a P6-style table; its expand button hides the tiles and adds a Gantt chart, and a P6 file adds the 4D timeline above the element table. Imported programmes are attached in step 3 of the IFC import; when absent the programme panel, 4D timeline and toolbar button are hidden. Seeded demo cards and reopened assets without a stored IFC model fall back to `demoData` elements. IFC assets/favourites persist in `apc.scan-assets.v1`.
- **Model** (`#/model`) is rail item 05 (QS Checking). Its home reuses the BIM to SMM Mapping home layout: header with a BIM to SMM Mapping button, search, grid/list toggle and mapping cards, filtered to scenarios that have mapped BIM elements. Clicking a card opens the model workspace (Properties, Project Browser, 3D, BQ table) with the selected project/model/standard and an `All projects` back button. The workspace currently renders the model module demo elements and BQ data while carrying the selected scenario's project/model context.
- **BIM to SMM Mapping** (`#/mapping`) is rail item 04. The home mirrors the AI Scanning library: search plus grid/list, a `Create Mapping` button in the page header, and scenario cards showing type, status, project, mapped progress and updated date. Create Mapping opens a single Link-CE-style dialog: scenario name at the top, then three stacked document-card lists — BIM model, Bill of Quantities and Activity Schedule — using the same document cards, checked circles and footer as the Link CE dialog. Choose one BIM model and either a Bill of Quantities or an Activity Schedule; selecting one quantity source clears the other, and Create Mapping stays disabled until BIM plus one quantity source are selected. The point cloud, master programme and cost review are not part of this module. New scenarios are saved in `apc.mapping-scenarios.v1`. Choosing Edit loads the IFC model and shows the BIM to SMM Mapping result: one 3D viewer plus an SMM mapping table with Element, IFC class, Storey, Material attribute, SMM library item, BQ item, Qty and Status; the Rule column has been removed. Material, SMM and BQ cells share the same 11.5px type. The SMM library item is the bridge: it shows only the library category (In-situ concrete, Precast concrete, Treatment to faces of in-situ concrete), and a BQ item is accepted only when it belongs to that library category and matches the material grade, cement and precast type; the IFC class is used only to choose between matching BQ items, not as a hard filter. There is no class-only fallback, so an unmatched material shows `—` and `Unmapped`. The 3D viewer colours mapped elements green and unmapped elements amber. Clicking a material cell opens a combo input with the existing material attributes and accepts a custom value following the same naming convention; Enter or blur saves, Escape cancels. The table toolbar filters All / Mapped / Unmapped, and Batch edit unmapped filters the unmapped rows and assigns one material to all of them. Material overrides persist in `apc.smm-materials.<scenarioId>`, and Reset edits clears them. The result header and scenario card show the selected BQ or Activity Schedule; the project standard is not shown per mapping model. The point cloud, master programme, progress bands and cost tabs live in AI Scanning instead.
- **Document Management** (`#/bill`) is rail item 01. Hovering 01 or its subnav expands a vertical 58px panel with **Pricing document** and **Invoice / DN**. Its top aligns with the 01 button and its first item shares the 01 vertical height. It has square left corners, rounded right corners, fits its two items, and collapses when not hovered.
- **Pricing document** is a page with the title `Pricing document` and one black **Import** button. Its four top tabs are flows: Bill of Quantity (BQ), Compensation Event (CE) and Activity Schedule. For NEC Option A/C the tabs are Activity Schedule first, Bill of Quantity as supporting reference second, Compensation Event third; Activity is selected by default and BQ is not required for Activity import. For Option B/D the tabs are Bill of Quantity and Compensation Event. Both BQ and Activity Schedule expose a bill/section sub-navigation list (Activity uses Schedule No. 1–13) (first import card labelled Activity Schedule, AS record codes and a Cleanse Activity Schedule heading), . The pricing import popup now handles three types: BQ (or Activity Schedule), Special Preamble and Particular Preamble; Drawing has been removed from the current-stage workflow. The page and popup are white. The import popup opens only from Import, has a top-right close button, and uses a white blurred scrim over the whole page to block background interaction. It provides three 4:3 cards, one per type, each with its own upload progress bar. Multiple files are allowed per type. Empty cards show the supplied BQ/SP/PP/Drawing artwork, title, drag/drop copy and supported formats; one inserted file replaces that with the type badge, file name, size, progress and status; two or more files switch the card to a compact per-file table with size, progress, status and remove. Next Step remains clickable, but with a missing type it turns the empty card light red with a Required marker and shows an error in the footer. The popup scrolls internally after 660px. The footer counts imported documents, and Next Step processes only when all four types have a ready file. Next Step opens a 10-second processing popup with a green progress ring and three stages: PP vs SP, Drawing vs BQ missing-item check, and CE updates. Completion shows a tick and **See Preprocessing Result**. The result replaces the page body with a three-column workbench: input package/configuration and processing logic on the left, the tabbed document viewer in the centre, and dashboard KPIs plus the Missing Item / PP Override report on the right. Step labels and explanatory copy are removed. The report uses the dense QS-review BQ-panel table style: surface-2 header, full cell borders, compact padding, single-line ellipsis and horizontal scroll. The missing-items report has no status column or row extras. The BQ record table keeps BQ record, Record ID, Processed and Status. A BQ home button returns to the document page. Document metadata and record status persist in localStorage across module navigation. Clicking a diagnostics row switches to the target file/page and highlights the source line (Drawing page 4 for CHK-01, PP page 6 for CHK-02). **Confirm & generate Cleanse BQ** Confirm first shows a white blurred overlay with a white spinner for about 1.8 seconds. Clicking the Pricing document subnav remounts the module at the BQ records list. The BQ flow tab also returns to the BQ records list; the separate BQ home button, Cleanse BQ subtitle and CE-total KPI are removed. Cleanse rows affected by the injected 3.01.09 item and the active PP override (2.10–2.12) use the same blue selection highlight as a selected BQ row. shows the Cleanse BQ inside the body using the old BQ table format, with the injected 3.01.09 grout item and a Download Cleanse BQ action. No backend PDF parsing or export service exists; the viewer and reports are demo data. The BQ page lists only BQ records; imported documents are no longer shown there. Import always starts a new workflow and creates a new record. Pending records open the result, confirmed records open the Cleanse BQ. A ⋯ menu on each record opens Preprocessing result (with the action “Submission Additional document and Reprocess”, reopening the workflow with that record’s documents attached) or Delete. Result/Cleanse panels use the same 30px header spacing and square corners as the QS BQ panel. Records persist in `apc.documents.v2` with automatic migration from v1. Processing completion adds a BQ records table to the BQ page: status is Pending (yellow) until Cleanse BQ is confirmed, then Confirm (green). The record opens the result, and BQ documents returns from the result.
- **Measurement Library** (`#/library`) is rail item 02 and is complete. Its next maintenance work is data-driven rather than layout work. It mirrors the old IFC QTO measurement-rules page: CESMM/HKSMM standard selector, 27-section tree, item search, SMM item detail with item name, measurement groups in BQ table style, editable mapping rows, and a final Calculation rule section (unit, formula, HKCESMM measurement rules with fixed marker space and no clause numbers) (slot, maps-to, display name, IFC attribute, separator, regex, delete). Add mapping row and Try a sample are supported. HKSMM currently shows an empty state.
- **Project Browser** lists IFC files and class groups. Drawings and 360 views are nested under the file that contains them; 360 rows appear only after the 360 section is enabled. It has a close button in its header. The left dock mirrors the right dock: draggable width with the initial width as minimum and 3px stacked separators. When an element is selected, Properties sits above the Project Browser. Project Browser has its own visible vertical scroller.
- **Properties** opens above Project Browser. With no selection it shows the centred message “Select Element to View Properties”. It starts with the element mark and name in the BQ Details title style and uses the BQ Details table style (white surface, full borders, grey headers, mono numerics). It shows Document & Contract Context, CIC / Cleanse BIM attributes, SMM measurement snapshot and Measurement basis (SMM). The basis block gives the rule reference, measurement basis, formula, exact calculation, less openings and net volume. The old subtitle, status badge and CIC audit row are omitted. Closing Properties only hides the window; selection, HUD and dimensions remain, and the Views modal reopens it.
- **View Function Bar** is a full-width glass bar at the top of the 3D canvas. It has a Tiles button followed by Plan, N, E, S and W. The default is only the Perspective view; enabling all five views gives six tiles. Turning Tiles off returns to one perspective view. The tile grid sits above the BQ strip when tiled.
- **Canvas context menu** opens on right-click over any model view. It contains Show Properties, Isolate, Hide Selected, Show All Objects, Focus, Pivot, Clear Selection, Align to 2D, a disabled Paste row, and a Section submenu with Section Box and Section Plane.
- **Action toolbar** uses dark rounded groups with white line icons. In normal mode it contains navigation (Orbit, Pan, Zoom, Walk, Fit, Reset), Section box and Section plane, and the measurement entry. Hovering any button shows its function name immediately. The active tile receives the actions; Walk uses W A S D. Select, isolate, hide, show all, clear selection and explode are not on the toolbar; those inspection actions remain in the right-click menu.
- **Section controls** open above the toolbar when Section box or Section plane is active. Section box exposes X/Y/Z min and max values; Section plane exposes an X/Y/Z axis and its coordinate. Every coloured section face is draggable in the model and updates the numeric fields live. The panel closes with its header X or by clicking the toolbar section button again.
- **Measurement mode** replaces the toolbar with navigation plus Distance, Angle, Spot coordinate, Laser, Surface, Shortest distance, Units/Precision and a green Done button. The status pill names the active tool, its next step and the active snap. While measuring, hovering geometry shows snap indicators: a square for a nearby vertex, blue lines for a nearby edge, and a faint blue face where the ray hits. Occluded vertices and edges behind a visible face are excluded. Tab cycles the active candidate and always includes a free cursor option, so the user confirms the snap instead of it being applied silently. Distance and Angle accept points and lines only; Surface accepts faces only; Spot coordinate and Laser accept points and faces; Shortest distance accepts any hit on two elements. Wrong hit types show a short rejection message. Distance picks two accepted hits; Angle picks three; Spot coordinate picks one; Laser picks one and gives the vertical offset to the nearest level; Surface picks three or more face points and Done commits the polygon; Shortest distance reports the nearest gap between two elements. Done exits the mode without deleting annotations. Measurements remain projected on the model, persist across tool and view changes, and are removed only by clicking the annotation, right-clicking and choosing Delete measurement.
- **BQ Details** opens as a right-side dock when a BQ row is clicked, pushes the canvas left, fills the full height above the BQ strip, and closes when the same row is clicked again, from its header X, or when the BQ strip is hidden. Selecting a BQ item also isolates its member elements in every 3D tile; closing it restores all objects. It has three sections: 1) BQ and valuation summary (BQ item, contract quantity/rate/amount, BIM quantity, BIM/BQ difference, cumulative verified quantity/percentage, cumulative certified amount); 2) BQ original and measurement basis with a measurement-group block (section title, measurement unit and measure type, numbered groups with descriptions), rule/basis/source/rounding, an Including/Excluding table, and a filterable BIM mapping table (component, location, IFC type, BIM quantity, adjustment, accepted quantity) whose rows select the corresponding model element; 3) period quantity verification with all interim certificates plus cumulative and remaining rows inside the same table, in YYYY/MM/DD and with BIM-quantity percentages. BQ quantities show two decimals.
- **Dock behaviour** has no top inset, uses 3px separators, and lets the QS drag the left edge to widen the dock. The right dock clamps at 460px minimum; the left dock keeps its initial width as the minimum. BQ Details, docked drawings and 360 views share the right dock; each boundary has a drag handle for height. The left dock uses the same width and height separation for Properties and Project Browser. The measurement-group block uses the BQ table type scale and padding. The width handle is one 2px blue line on hover.
- **Table style** follows the BQ panel: white surface, full cell borders (including top and right), grey header row, 11.5px body text and mono numeric columns. BQ Details tables cap at 10 visible rows and scroll vertically beyond that. Summary, basis, mapping, scope and payment tables use this shared style, as do other product tables.
- **Money permission** is resolved before data loads. A normal member receives no money fields in the data object, and money-only sections/rows/columns are not constructed at all. Never hide money with CSS. The demo scaffold is `src/lib/permissions.ts`; real enforcement belongs on the server.
- **View tiles** are Perspective, Plan, North, East, South and West. The active tile gets a blue outline only when more than one tile is shown; one glass action toolbar at the bottom acts on the active tile.
- **Drawing popup** opens docked at the right by default. It has a close button, a Float button, drags by its header after floating, shows a blue dashed dock preview while near the right edge, snaps into a square-cornered dock, and resizes from the corner (min 320 × 240, max 900 × 700). Clicking elements selects them and updates the model.
- **360 popup** is enabled from Views and opens docked automatically with the first walkthrough. It shows a draggable panorama and uses the same Float/dock behaviour. It is not listed in the Project Browser.
- **Right dock** takes physical width from the 3D canvas. One docked view gives a two-window split; two docked views stack 360 above the drawing at 50/50 height. Docked views have square corners and a Float button to return them to the canvas. The view grid stays inside the remaining 3D canvas; the BQ strip spans the full workspace width below both.
- **BQ strip** is a solid white, read-only table spanning the full workspace width below the canvas with a 350px minimum height and dock. Its top edge drags between 120px and the smaller of 620px / viewport height minus 170px. Its header holds the item search. It toggles from Views; Qty/Rate are not editable here (the Bill page keeps the editable table).
- **BQ table** columns are fixed-width and resizable from every header edge. Dragging one column changes only that column and pushes the columns to its right; content crops with an ellipsis. The last column fills the remaining table width. Columns are Item, Description, Unit, Qty (BIM), Qty, Rate, Amount HK$ (BIM), Amount HK$.
- **Bill-page BQ editing** lets the QS type a Qty or Rate. The value commits on blur or Enter, updates the row amounts immediately, and is shared with the model BQ strip because both read the same project state. A blank Qty/Rate clears the edit. The strip itself stays read-only.
- **BQ search** filters item rows by item number or description while keeping the matching section and group headings.
- **BQ line badge** is a read-only popup, hidden by default. Its width resizes from the right edge (min 320, max 560).
- **Element properties** is a read-only popup, hidden by default, opened from the Views modal.
- **Tool rail** switches pages by URL. Bill is a full page with the same resizable/editable BQ table; Data and Mapping are built; Review is a routed page awaiting its content. No routed page has a top header bar.
- **View submenu** lists every closable window: Properties, BQ Details, BQ line badge, Drawing viewer, Master programme (mapping route only), Project Browser, Glass toolbars, BQ list strip and 360 views. The window toggles keep the menu open and show a checkmark; the others are persistent sections. Checkmarks in the logo submenu update immediately when a section is toggled.
- Tags and helper copy about a function are removed from the workspace. Tooltips remain as 3-second hover hints.

The design reference is the external handoff folder `E:\Project\design_handoff_qs_model_verification`. It is a prototype, not production code. The port keeps its tokens, classes, behaviour and demo values, but uses React components and a typed data module.

Real IFC parsing, the rule engine (M06/M08), persistence and the backend save endpoints are not wired yet. `src/lib/demo.ts` is the stand-in for `APC_LOGIC`.

## Run

- `npm run studio` from the project root, or `npm --prefix studio run dev`. Vite serves on port 5173.
- Optional: `cd demo-backend; npm start` serves the demo API on port 8781. The AI Scanning page uses it when reachable and keeps working without it.
- `npm run studio:build`, then start the Node server. The app is at `http://localhost:8780/studio/` from `studio/dist`.
- `npx tsc --noEmit` and `npx vite build` must pass before a change is handed over.
